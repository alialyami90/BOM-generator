Device library data brief

You will read manufacturer datasheets and record each part's electrical and physical data in three CSV tables. This page says what to put in every column, how to cite where each value came from, and how your delivery will be checked.

Files sent with this page: blank template, worked example, list of existing parts with gaps Format: the generator's own Library CSV tables

What to send back

One folder (or a .zip of it) per delivery. Start from the blank template files so the column headers are exact. Do not rename, reorder or delete columns.

File rules

Save as CSV UTF-8In Excel: Save As, then "CSV UTF-8 (Comma delimited)". Comma or semicolon separators both read.
Decimal point12.5, not 12,5. No thousands separators, no units in the cell.
Exact spellingAllowed values are case sensitive: VDC not DC, CONTINUOUS not continuous, low not Low.
No formulasType values. A cell starting with =, + or @ is flagged.
Guard part numbersExcel turns codes like 3-12 into dates and 1E10 into numbers. Format those columns as Text before typing.
Unknown means blankLeave a cell empty when the document does not give the value. Never write 0, TBA or a guess in the value cell.

Alternatives

Each alternative part is its own row in devices.csv with its own data and sources. Parts that can replace each other share an alt_group.

  • For a part already in the library, use the alt_group from the worklist. It is usually the original's part_id, e.g. RST2228-L2.
  • Name an alternative <original part_id>.<BRAND>-<TIER>, brand in capitals with hyphens for spaces: SEL-2488.MEINBERG-LOW, SEL-3555-GW.HITACHI-ENERGY-MID.
  • Give the original part the same alt_group and a blank tier.
  • Aim for two brands other than the original, each with a low, mid and high part. If a brand has no distinct high part, skip that tier and say so in a note.
  • Record an alternative even if it cannot take 125 V DC or 230 V AC. Give its real supply, and write "needs converter" in the note.

How your delivery is checked

  1. Import dry run. Your rows are merged onto the current library and run through the generator's own Library CSV import without saving. It checks file encoding, column names, allowed values, number formats and cross-field rules, for example that only VDC parts have power_supplies above 0 and that input_v_min is not above input_v_max. Any row that fails is returned with its row number and the reason.
  2. Source coverage. Every filled value must have a sources.csv row with a matching value, an existing PDF in pdfs/, a page number and a revision. Every powered part needs inrush and input range rows, filled or not_given.
  3. Sanity checks. The nominal voltage must sit inside the input range. Power must be plausible for the part type. Every row in an alt_group must name the same function, and each brand should cover low, mid and high.
  4. Spot check against the PDFs. A sample of values is read back from the cited page, including every inrush figure and every corrected value. If more than a few in the sample are wrong, the delivery is returned for a full recheck.
  5. Report back. You get one list of problems by file, row and column. Once it is clean, the delivery is imported as a new library version.
