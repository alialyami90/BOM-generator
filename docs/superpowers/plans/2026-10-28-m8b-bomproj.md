# M8b `.bomproj` Export, Import and Backup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Share a project between engineers as one `.bomproj` file, and keep timestamped backups of it.

**Architecture:** The zip container (deterministic write, path and case checks, size cap, checksums) moves out of `library_store` into a shared `bomgen.bundle` package; `.bomlib` and `.bomproj` both use it. A new `bomgen.project_store` holds the project manifest, export, import (workspace, overwrite rules, library-version note) and backup. Refusals stay `LibraryPackageError` with new `RefusalKind`s.

**Tech Stack:** Python 3.12 stdlib (`zipfile`, `hashlib`), pydantic v2, PyYAML, typer.

**Spec:** ADR 0012 and `docs/superpowers/specs/2026-10-28-substations-and-auto-layout-design.md` section 2; plan M8b.

## Global Constraints

- `.bomproj` = zip of one project folder without any `out/` directory, without `Backups/` and without `*.bomproj` files, plus `manifest.json`: `format_version` (1), `project_id`, `library_name` and `library_version` (null if `project.yaml` has no `library`), `app_version`, `created`, `files` (posix path → SHA-256).
- The project id and library come from `project.yaml` (`project.id`, `library.name`, `library.version`), read as plain YAML so M8b does not depend on the M1b models.
- Workspace: `BOMGEN_WORKSPACE`, else `~/Documents/BOM Generator` (`%USERPROFILE%\Documents\BOM Generator` on Windows). A project lives in `<workspace>/<project-id>/`.
- Import never writes before every checksum and path check passed. An existing project id is refused unless `force`; a forced import first backs the old project up to its `Backups/`, keeps its `Backups/` and `out/` folders, and a failure restores the old project.
- Backup file: `<project>/Backups/<id>-<YYYYMMDD-HHMMSS>.bomproj`.
- Existing `.bomlib` behaviour and tests do not change.
- Never write `.xlsx`; tests write only under `tmp_path`.

## Review Focus

1. A project folder containing symlinks, `out/`, `Backups/` or an earlier `.bomproj` must not leak those into the package or follow links out of the folder.
2. A hostile project id (`../x`, `con`, `a/b`) in a package or `project.yaml` must never place files outside the workspace.
3. A forced import that fails half way must leave the previous project, its `Backups/` and its `out/` untouched.
4. A `.bomlib` given to `project import` (and the reverse) gets a clear message, not a pydantic dump.
5. Two backups in the same second must not overwrite each other.
