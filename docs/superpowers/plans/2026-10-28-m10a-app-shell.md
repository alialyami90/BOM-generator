# M10a Desktop app shell Implementation Plan

**Goal:** Open the approved M9 design in a native pywebview window, with a typed
Python API the UI calls, so the following M10 PRs only wire screens to engine
functions.

**Architecture:** `src/bomgen/app/ui/` holds the prototype's HTML/CSS/JS and fonts,
loaded from disk (`file://`, no server, no port). `bomgen.app.api.Api` is passed as
pywebview's `js_api`; every public method returns a JSON envelope
(`{"ok": true, "data": …}` or `{"ok": false, "error": {"kind", "message"}}`).
`ui/bridge.js` is the only JS that talks to `window.pywebview.api`.
`bomgen.app.window.run_window` is the one call the launcher makes.

**Tech Stack:** Python 3.12, pywebview 6.2 (Edge WebView2 on Windows), vanilla JS.

**Spec:** `docs/ui/screens.md` ("What the app needs from the engine"), ADR 0007,
ADR 0009, ADR 0011, `docs/plan.md` M10.

## Global Constraints

- `bomgen.app.__init__` stays import-free (ADR 0009); `webview` is imported only
  inside `run_window`.
- No business rule in the UI or in `bomgen.app`: the API calls engine and store
  functions and reshapes their results for JSON, nothing else.
- Works offline: no `http:`/`https:` URL in any UI file; fonts are bundled.
- Minimum window 1280 × 720 (`screens.md`, "Scaling").
- pywebview is the optional extra `app`, `pywebview>=6.2,<7`; nothing imports it at module level, so `dev` does not need it.

## Review Focus

- No WebView2 runtime or no GUI backend: `run_window` must tell the user what
  to install and return 1, not crash with a traceback in a windowless exe.
- An unexpected exception inside an API method must reach the UI as an error
  envelope (`kind: "internal"`), never as an unhandled promise rejection with no text.
- A damaged library store (`RefusalKind.STORE_DAMAGED`) must not stop the app
  from starting: `app_info` reports the library with its problem.
- The UI copy must not drift from the design: `tokens.css` and the fonts are
  byte-identical to `docs/ui/`.
- UI opened in a plain browser (design review) must still render, with the
  bridge reporting that no backend is present.

### Task 1: API envelope and `app_info`

**Files:**
- Create: `src/bomgen/app/api.py`
- Test: `tests/unit/app/test_app_api.py`

**Interfaces:**
- Produces: `class Api(project_file: Path | None = None, env: Mapping[str, str] = os.environ)`;
  `Api.app_info() -> Envelope` with `data = {"title", "version", "project_file",

  `endpoint` decorator; `Envelope = dict[str, object]`.
