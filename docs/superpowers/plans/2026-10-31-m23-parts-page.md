# M23 Parts page in the app Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this
> plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the app's Network page with the Parts page designed in M22, on M20's model fields,
with the writers that keep `substation.yaml` clean (an override equal to the library value is never
written).

**Architecture:** M20 already validates `Equipment.ordering_code`, `overrides` and `sfp`, and the
generic field writer (`io/fields.py` `set_field`/`remove_field`) can write any of them. M23 adds:
- `app/parts.py`, which flattens one substation into the page's rows with each row's library values;
- `io/parts_edit.py`, five writers whose rule the generic writer cannot know;
- the Api endpoints;
- `screens-parts.js`, which replaces the Network screen.

The engine is not changed.

**Tech Stack:** Python 3.12, pydantic v2, ruamel.yaml, pytest, ruff, mypy; vanilla JS in
`src/bomgen/app/ui/`; Playwright for the E2E check.

**Spec:**
- `docs/superpowers/specs/2026-10-31-part-picking-design.md` §3, §4 and §7.1–7.2.
- The approved M22 design: `docs/ui/screens.md` "Parts (M22, replaces Network)", `docs/ui/components.md` "Parts and Device preview (M22)", and `docs/ui/editing.md` "Substation › Parts (M22)" (the field table: control, YAML key and validation sentence for each field).
- ADR 0024.

## Review Focus

1. **An override typed back to the library value** is removed from the file, not written. When the
   last one goes, the empty `overrides:` mapping goes with it, and the file reads as it did before the first override.
2. **A sized L1 row with no part** has no details strip, SFP or part number controls. If an
   override is sent for it anyway, it is refused with the model's sentence "pick the switch to
   override its data".
3. **A row whose part is not in the active library** still loads. The row shows the id in error with
   "Not in <library> <version>. Pick another part." and `library: null`. Picking another part fixes it.
4. **A new substation saved with some rows unpicked.** The rows with a part are written together with
   the L1 row, in one write. Unpicked rows are dropped. With no L2 switch picked, the save is refused with
   "Pick the L2 switch first: the network is sized from it."
5. **Reordering rows** changes the panel fill order (ADR 0013), and every row keeps its `id`, so pins in
   `layout.overrides` survive the move.

### Task 1: The page data

**Files:**
- Create: `src/bomgen/app/parts.py`
- Test: `tests/unit/app/test_app_parts_api.py`

**Interfaces:**
- Produces `parts_page(project_file: Path, substation_id: str, store: LibraryStore) -> dict[str, Any]`:
  `substation_page(...)` plus a `"parts"` key holding:
  - `rows`: one per equipment entry, in file order. Each row is `{index, id, role, label,
    category, part_id, known, ordering_code, qty, sized, redundant, cable_manager, library, overrides, sfp,
    accessories}`.
    - `cable_manager` is `Equipment.cable_manager` on a network row, and `None` on any other row. A network row is one whose part's category is `network_switch`, `patch_panel`, `firewall` or `gateway`.
    - `library` is the *base* part's `{height_u, unit_power_w, supply_type, voltage_v,
      power_supplies, inrush_a, load_type}`, or `None` when there is no part or it is unknown.
    - `overrides` is `PartOverrides.values()` or `{}`.
    - `sized` is true for L1 and L2.
    - `sfp` is `[{speed, media, choice, candidates}]`, with one entry per (speed, media) the switch's port allocations use in `layout_preview(loaded)`.
    - `accessories` is on the time server row only, and empty on the others. It holds two lists:
      - `library`: the picked part's `loose_items`, read-only, as `{part_id, qty}`. The engine already ships these as loose material.
      - `added`: the `loose_material.items` rows linked to this row, as `{index, part_id, qty}`. `index` is the row's place in `loose_material.items`.

      **The link** (decision 2, no model change):
      - A loose item belongs to the time server row when its `part_id` is in `time_accessory_parts`.
      - That set is the time server part's `loose_items` part ids, plus the accessory parts the library lists as their alternatives.
      - The accessory picker offers exactly that set.
      - A loose item of one of those parts added on the Loose material page shows here too, because it is the same thing.
      - A free-text loose item never links.
      - With no time server part picked, `accessories` is empty and the picker is absent.
  - `options`: for each category, the active library's parts as `{part_id, make, model}`.
  - `default_rows`: the §3 row order as `[{role, label, category}]`, which the page offers when the substation has no equipment yet.
- `ROLE_CATEGORY` maps each role to its category:
  - `time_server` → `gps_clock`
  - `l1_switch` and `l2_switch` → `network_switch`
  - `operator_ws`, `engineering_ws` and `da_server` → `workstation`
  - `kvm`, `console` and `annunciator` → the category of the same name
  - `firewall` → `firewall`
  - `fopp` → `patch_panel`
  - `ext_switch` → `network_switch`
  - `other` → every category
- `time_accessory_parts(library: Library, part_id: str) -> frozenset[str]` returns the link set described above.
- `ROLE_LABEL` holds the row labels in the M22 wording ("Time server clock", "L2 switch", …).

### Task 2: Writers the generic field writer cannot do

**Files:**
- Create: `src/bomgen/io/parts_edit.py`
- Test: `tests/unit/test_parts_edit.py`

**Interfaces** (each takes `*, store: LibraryStore | None = None`, returns `EditResult`, and writes only
when the edit adds no problem, as `io/edit.py` does):
- `set_override(project_file, substation_id, index: int, field: str, value: object)`:
  - `value` is `None`, or equal to the base library part's value → the key is removed.
  - Removing the last key removes `overrides`.
  - A `field` that is not on `PartOverrides` → `EditError`.
- `set_sfp_choice(project_file, substation_id, index: int, speed: str, media: str, part_id: str | None)`:
  - Replaces or adds the entry for that (speed, media).
  - `None` removes the entry, and the last removal removes `sfp`.
- `set_equipment_part(project_file, substation_id, index: int, part_id: str)`:
  - Writes `part_id`.
  - Removes `overrides`, `sfp` and `ordering_code` (decision 1): they belonged to the old model.
  - Writes nothing when `part_id` is unchanged.
- `set_cable_manager(project_file, substation_id, index: int, on: bool)`:
  - `False` writes `cable_manager: false`.
  - `True` removes the key, because on is the default.
  - Refused on a row that is not a network row.
- `move_equipment(project_file, substation_id, index: int, to: int)`: reorders `equipment`. It keeps
  the comments that ruamel attaches to the moved item.
- `start_parts(project_file, substation_id, rows: list[dict[str, Any]])`:
  - Refused unless `equipment` is empty.
  - Drops rows with no `part_id`, except L1.
  - Adds `{"id": "l1", "role": "l1_switch", "redundant": True}` when no L1 row is given.
  - Refused with "Pick the L2 switch first: the network is sized from it." when no L2 row has a part.
  - Ids come from the role (`gps`, `l2`, `l1`, `ows`, `ews`, `da`, `kvm`, `console`, `ann`). Each one is checked unique.

## Decisions (A1, 2026-10-31)

1. **Changing a row's part clears its overrides, SFP choices and part number.** A part number belongs
   to the old model, so keeping it would print a wrong number on the BOM without anyone noticing.
   Cleared, the BOM falls back to the library's code and the M20 warning shows. The change toast says so.
2. **Time accessories are written as loose material items.** They are linked to the time server row
   by part, as in Task 1, with no model or engine change. `editing.md` is amended in this PR.
3. **The annunciator's "Mount in panel" switch** (design §10) stays out of M23. It is Q51 in
   `docs/plan.md`.
4. Removing `start_equipment` and the L1 ranking payload is fine once nothing calls them.
5. **Ali's M22 approval (2026-10-31) adds a "Cable manager" switch** to each network device row,
   on by default. A3 adds `Equipment.cable_manager: bool = True` first, in a small engine PR. M23's
   cable-manager parts wait for that PR, and the rest of M23 does not.
